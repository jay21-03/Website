# Analytics Metric Catalog

Phase 0 audit, 2026-10-24. This catalog separates website activity measured by GA4 from store records held in PostgreSQL. A supported API field is not proof that events reach the configured Property.

## Conventions and evidence

- Availability: `AVAILABLE` means the schema and a read-only Production query support the measure, including a legitimate zero. `DERIVED` requires the stated denominator; an undefined result is displayed as unavailable. `TRACKING_REQUIRED` means source events are incomplete or unverified. `INTEGRATION_REQUIRED` means an external mapping or read permission is unverified. `UNSUPPORTED` means the current records cannot establish the measure.
- GA4 dates use the Property timezone reported by Core Data API metadata: `Asia/Saigon`; currency is `VND`. Historical reports must end at yesterday in the Property timezone. Realtime uses the last 30 minutes, not a precise concurrent connection count. GA4 Data API Metadata, Core `runReport`, and Realtime `runRealtimeReport` returned HTTP 200 for Property `560090227`; Core currently returns zero rows. Core `checkCompatibility` returned COMPATIBLE on repeat, with one transient HTTP 503 between successes. The user verified in ordinary Edge that a consented `page_view` to Measurement ID `G-BB79X513WR` returned HTTP 204 and GA4 UI Realtime showed one active user and four page views (two each on `/` and `/san-pham`). The later Backend WIF `runRealtimeReport` returned HTTP 200 with one row: activeUsers=1, screenPageViews=4, eventCount=7, keyEvents=0. An earlier Chromium automation probe reported `net::ERR_ABORTED`; that result did not reproduce in the user's ordinary browser. Analytics Admin API confirmed `G-BB79X513WR` belongs to web stream `16179028870` of Property `560090227` in account `412902812`; the Property was created at `2026-10-22T05:38:25.460Z`, and registered key events are `purchase`, `close_convert_lead`, and `qualify_lead`. The Backend uses external-account WIF to impersonate `ga4-report-reader@webgom.iam.gserviceaccount.com` in Google Cloud project `webgom` (`280875506130`). An exploratory 12-metric Core request returned HTTP 400 `INVALID_ARGUMENT`; no unverified metrics from that combination were added to the dashboard.
- Business dates use `Asia/Ho_Chi_Minh`, with `[start, endExclusive)` database instants. “Current status” reports describe the present state, not a reconstructed historical snapshot. Monetary values are integral VND. Workshop booking prices are not payment records. Chat history is retained for 60 days after closing.
- Production read-only checks: Flyway V22; one `CANCELLED` order with `EXPIRED` payment, no paid/completed orders or reviews; one `NEW` workshop booking with 10 participants; five active customer accounts; six notification records and 30 Admin recipient records (seven read); four retained Chat conversations (one open); one current low-stock product. These are observations, not test fixtures.
- Validation methods below refer to `BE/src/main/resources/db/migration/`, `ReportingRepository`, direct read-only PostgreSQL queries, and GA4 Data API responses. No customer identity or message content is used.

## Deployment gate

Stream mapping, registered key events, browser collection, GA4 UI Realtime and Backend WIF Realtime are verified. The Phase 0 source gate is satisfied for Realtime. Historical Core still has no rows, so implementations must present an honest empty state, account for the recently created Property and processing delay, and avoid inventing trends. No GA4 Property setting was changed by this audit. Existing Production reporting remains active (Backend systemd active and local health HTTP 200 after the audit).
